# Capture architecture investigation (T25)

The candidate keeps one shared, synchronous JSONL stream and reduces work under its append lock. Only a busy acquisition before any work can defer a sanitized observation into a bounded recorder-local FIFO. This recovers demonstrated transient overlap without a new service, IPC, spool, database or public setting. Filesystem calls remain synchronous and can exceed the retry policy's time budget.

## Chosen mechanism and alternatives

| Alternative                           | Benefit                                                                                                                                                                                                                                                    | Cost / reason for decision                                                                                                                                                                                           |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A: reduced critical section, no queue | Smallest state; synchronous completion. Keeps all namespace/header/generation checks.                                                                                                                                                                      | Earlier controlled overlap retained 0/2 admitted identities. Retained as an honest simpler fallback; insufficient for the demonstrated transient overlap objective.                                                  |
| A+B25 (chosen)                        | Same synchronous fast path; retry only an acquisition refusal before work. Earlier scratch comparison retained 2/2 under the same controlled release; final typed multiprocess regressions independently require retained identities and all four origins. | 16 pending snapshots, 64 KiB encoded snapshot budget, 25 ms monotonic retry age; a held preference FD per pending/in-flight observation plus transient FDs. Extra state, exit tail and volatile loss on abrupt exit. |
| B10 (scratch only)                    | Shorter policy window.                                                                                                                                                                                                                                     | Earlier bounded scratch run still had 6 client / 2 whole-daemon failures in concurrent search versus 0/0 for B25. Few uncontrolled samples do not estimate rates; not adopted.                                       |
| C: runtime-owned writer / IPC         | Could centralize writer ownership while runtime lives.                                                                                                                                                                                                     | Adds stopped-daemon behavior, transport failure, opt-out, shutdown and ownership complexity; no evidence that A+B requires it. Not implemented.                                                                      |

Snapshots freeze allowlisted primitives, UTC timestamp, span/context and generation at admission. FIFO ordering is per recorder, not global time. A preference FD binds to exact bigint device/inode identities validated under the append/witness gate; a rapid OFF→ON with the same generation invalidates old snapshots. The retry queue has one timer, one active drain and a fixed admission watermark/deadline. Overflow rejects the newest observation. No retry follows short write, write exception (including `EEXIST`), close or release failure. Complete byte count is capture evidence, not a power-loss durability promise.

The 64 KiB limit measures encoded snapshots, not all heap/FD overhead. A close error is sticky degraded health with one close attempt, never a blind second close of a potentially reused descriptor. Appends retain all caps, path checks, complete-header inspection, tail handling, generation validation and exact TTL; there is no cached/batched scan bypass. Configuration still returns a safe error on release failure even if rename occurred. No command/SDK/intent/receipt retry was introduced.

The 25 ms policy is **not** a wall-clock guarantee: scheduler and synchronous filesystem work can overrun it. The earlier scratch real-clock expiry control took 33.60 ms; the productive real-clock regression requires expiry with no retained row while the independent holder remains. Fatal exit and a process that skips owner close can lose pending observations before discard accounting/witness; a new recorder's zero remains compatible with that loss.

Later report-only commits do not change these measured modules. Node 24.18.0, pnpm 10.24.0, TypeScript 5.9.3 and the same frozen dependencies were used. Whole-daemon counters include startup/status/stop/shutdown and cannot be assigned solely to measured search/replay commands. Legacy failures also include outcomes now separated as uncertain/cleanup; the old and new totals are not semantically identical loss estimates. Candidate terminal recorder accounting reconciles admitted = captured + known incomplete + uncertain + invalidated, with pending zero in these runs. The search daemon deferred 19 observations, peaked at six pending snapshots / 3,444 encoded bytes; replay peaked at one / 889 bytes. Other recorders also stayed within 16 / 64 KiB. A witness-free page, zero counters or more retained rows does not prove completeness. Controlled identities, mutation/FIFO, real expiry, opt-out, overflow, write faults and lifecycle regressions supply causal evidence separately.

Historical benchmark reports in [observability](../operations/observability.md) remain evidence only for their exact sources. The scratch A/B results informed the choice and are distinguished above from productive source checks. Neither reproducing a possible schedule nor this comparison identifies the real historical witness's cause.
